# Case variations

Three authored scenarios per case: the existing original plus two alternate culprits. Variants retain each case's central puzzle and vocabulary, but change the relevant access/observation records, chronology and, where appropriate, destination. Roles stay recognizable; an alternate's access must be explained in its actual records. These are bounded authored recipes, not AI generation or unrestricted clue shuffling.

Persist an opaque scenario ID in the shared match. Resolve all clues, profiles, hints, answers and debriefs from that ID. Selection is deterministic from the match seed; transaction retries and reconnects never redraw. A deliberate new-scenario action excludes the current scenario. Replaying the same scenario resets the investigation but retains its ID. Revising a failed theory retains both ID and notebook.

After finishing: Reveal (explicit confirmation, shared for the whole crew), Replay same scenario, New scenario. Reveal never changes an unsuccessful result to solved. Existing answer revision and other-case selection remain available. A reveal permits the current scenario's full explanation and missed evidence; it never reveals a different variant. New matches reset disclosures and reveal state.

Verification must enumerate all 24 scenarios, check three distinct culprits per case, coherent dated records and chronological orders, vocabulary/dependency integrity, correct and incorrect submissions, replay identity, guaranteed different draws, reveal permissions, stale commands, and local/online persistence. Record where variants are edited for the maintainer. Ratings remain those of the underlying case.
